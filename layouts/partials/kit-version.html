OPT-IN: the kit has no footer of its own (every landing writes one), so a landing that does not call this gets the page it had, byte for byte, and `landingkit audit` reports it as "none". It reads hugo.Deps, the module graph Hugo resolved, for the dependency whose Path is the kit's, and prints its Version linked to that release: landingkit v0.36.0 -> .../releases/tag/v0.36.0 Three cases, and none of them may fail the build: - a tagged version: linked to its release; - a pseudo-version (a branch or commit pin, v0.36.1-0.2026…-abcdef123456): shown as it is, linked to the commit, since no tag exists for it; - a `replace` to a local directory, or no such dependency at all: the Version is then the REPLACED one (the example's go.mod still says v0.14.0 and would print it), so it is not trusted: "landingkit (local)", no link.
